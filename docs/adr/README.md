# Architecture decision records

Choices not covered by the spec, approved by the maintainer, one file per decision. To add one: get a number from the orchestrator (never take the next free one yourself), copy the template below to `NNNN-<kebab-slug>.md`, fill it in and list at least two options under Options considered. The index below is generated by `scripts/dev/render-adr-index` in the orchestrator's sync PR (ADR-0036); a track PR adds only the ADR file. Status is one of `Proposed`, `Accepted` or `Superseded by ADR-NNNN`; a new ADR stays `Proposed` until the maintainer approves it, then becomes `Accepted`. Never edit the decision of an accepted ADR; write a new ADR instead. Amend only to add something, where nothing in the old ADR becomes wrong: add `Amends: ADR-NNNN` to the new ADR and `Amended by: ADR-NNNN` to the old one. If any part of an old decision is removed or reversed, write a new ADR that states the full current decision, add `Supersedes: ADR-NNNN` to it, and set the old one's Status to `Superseded by ADR-NNNN`. The alias `D<n>` keeps older mentions such as "(D4)" resolvable.

## Template

```markdown
# ADR-NNNN · <title>

- Status: Proposed
- Date: YYYY-MM-DD
- Deciders: maintainer
- Alias: `D<n>`
- Supersedes: ADR-NNNN (omit if none)
- Superseded by: ADR-NNNN (omit if none)
- Amends: ADR-NNNN (omit if none)
- Amended by: ADR-NNNN (omit if none)

## Context

<the problem or constraint that forced a choice>

## Options considered

- <option>: <pros>; <cons>
- <option>: <pros>; <cons>

<why the rejected options were rejected>

## Decision

<what was decided>

Why: <rationale>

## Consequences

- <what follows from it>
```
